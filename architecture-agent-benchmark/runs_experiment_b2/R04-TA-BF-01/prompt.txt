## Ticket: Renaming a drawing can produce a file name that fails to save

Several users have reported problems after renaming a drawing right before saving it to
disk or exporting it. Depending on what they type into the name/title field, the save can
silently fail, get mangled by the browser or operating system, or overwrite an unrelated
file. Examples that have caused trouble: names containing `/`, `\`, `:`, `*`, `?`, `"`,
`<`, `>`, or `|`; names that are empty or made up only of spaces; and names that end with
a trailing dot or trailing spaces (Windows strips these silently, which can cause
mismatched file names between what the user typed and what got saved).

Please make renaming a drawing robust against this: whatever the user types into the
name field, the name that actually gets used when saving/exporting to disk should always
be a valid, safe file name on common desktop operating systems (Windows, macOS, Linux).
The user should still be able to type freely in the field, but if their input had to be
adjusted to make it safe, that should be visible to them rather than silently changing
what ends up on disk.

This only needs to cover the drawing's name/title as edited by the user in the editor —
no changes to unrelated import/export formats are needed.
