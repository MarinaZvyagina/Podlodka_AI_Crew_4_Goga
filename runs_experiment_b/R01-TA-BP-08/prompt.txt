We've had a handful of support requests from users who are confused about how their starting trading
capital is actually calculated. Some users set a fixed "total capital available for trading" amount in
their config, but *also* leave (or explicitly set) a "percentage of balance that's tradable" value,
expecting both to somehow combine. In reality, only one of these two settings ends up taking effect
depending on which is present, and the other is silently ignored — the bot doesn't tell them this is
happening.

We don't necessarily need to change which setting wins (that behavior is intentional and shouldn't
change). What we need is for the bot to catch this specific misconfiguration up front, before it starts
trading with capital sizing the user didn't intend, and fail fast with a clear, actionable message
explaining that only one of the two settings is in effect and the other will be ignored.

Please add this check. It should fire during the normal startup configuration checks (the same phase
where we already catch other conflicting or nonsensical config combinations, e.g. contradictory
stoploss/trailing-stop settings), not deep inside the trading loop, so users see the problem immediately
when they try to start the bot rather than after it's already running. A plain "one of these two values
will be ignored, please remove one" style message is enough — we don't need to guess which one the user
actually wants.


This repository has Goga tooling and skills available (already connected) if you find them useful for this task.
