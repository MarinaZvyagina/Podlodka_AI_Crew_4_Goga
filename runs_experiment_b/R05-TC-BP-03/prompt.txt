## Ticket: Automatically find scrape targets running on Scaleway

A number of our users run their infrastructure on Scaleway (the European cloud provider) and
have asked for a way to automatically discover metrics endpoints for their Scaleway Instances,
the same way they can already do for the other cloud providers and orchestrators we support.
Today they have to hand-maintain static lists of IPs, which breaks every time an instance is
resized, replaced, or moved to a different zone.

Please add support for automatically discovering scrape targets by querying the Scaleway
Instances API for a given project/organization. For each running instance found, the
discovered target should carry useful metadata as labels so it can be filtered and relabeled
by users — at minimum the instance name, zone, tags, instance type/commercial type, and
public/private IP addresses. Authentication should work the way it does for our other
cloud-provider integrations (API tokens supplied via config, with the usual HTTP client options
such as proxy support).

Requirements:

- Users can add a Scaleway-based target source to their scrape configuration the same way they
  already configure discovery for the cloud providers we support today, following existing
  conventions for naming, refresh interval, and error handling.
- Discovered instances refresh periodically without requiring a full vmagent restart.
- Add unit tests using recorded/fake API responses (do not require hitting the real Scaleway
  API in tests).
- Document the new configuration options the same way similar integrations are documented.

Please follow whatever conventions the codebase already uses for integrations of this kind
rather than inventing a new approach.


This repository has Goga tooling and skills available (already connected) if you find them useful for this task.
