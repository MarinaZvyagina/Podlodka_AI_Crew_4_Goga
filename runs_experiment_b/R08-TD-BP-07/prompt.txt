## Ticket: Repeated searches are slower than they need to be

**Reported by:** User feedback / internal dogfooding
**Component:** Chat list search

### Description

People search their conversations and messages fairly often, and it's common to search for the same thing more than once in a short span — for example, clearing a search by accident and retyping it, or leaving the chat list and coming back and searching the same term again. Right now every single search re-scans everything from scratch, even when nothing in the underlying conversations has changed since the last identical search.

### Request

Add caching so that repeating an identical search (same text, same filters) returns results noticeably faster than the first time, instead of always doing the full search again from zero.

### Important behavior to get right

- If new messages arrive, or existing messages/conversations relevant to a previously-searched term get edited or deleted, a later search with that same term must reflect the current state — no stale results.
- Different search terms should be cached independently of each other.
- Everything else about how search currently behaves (filters, snippets, result ordering) should stay the same.

### Acceptance criteria

- Typing the same search query twice in a row (with nothing else changing) is noticeably faster the second time.
- Data changes that affect a previously cached search term are reflected the next time that term is searched — nothing stale is ever shown.


This repository has Goga tooling and skills available (already connected) if you find them useful for this task.
