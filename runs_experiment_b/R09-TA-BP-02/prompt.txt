## Ticket: Orphaned backup files after removing a browser window's saved tab data

When a browser window is closed for good (e.g. the user removes a Firefox
window on iPadOS, or an old window is pruned during cleanup), we delete its
saved tab/session data from disk so it doesn't keep taking up space or show
up again on next launch.

QA noticed that after repeatedly opening and closing windows over many days,
the on-disk profile folder keeps growing even though the "current" window
data files are correctly removed. Digging in, it looks like we keep a
slightly older backup copy of each window's data (used for recovery if the
main copy gets corrupted), and that backup copy is never cleaned up when the
window itself is removed — only the primary copy is deleted. Over time this
leaves an ever-growing pile of stale backup files for windows that no longer
exist.

Please fix this so that when we remove the saved data for a window (or a set
of windows), both the primary copy and its backup copy are deleted. Removing
data for windows that don't have a backup file should continue to work
without error, and windows that aren't in the list to remove must be left
untouched (including their backups).


This repository has Goga tooling and skills available (already connected) if you find them useful for this task.
