## Ticket: Orphaned thumbnail cache files never get cleaned up

**Reported by:** Internal storage audit
**Component:** Attachment/media storage

### Description

When people view photos and videos in the app, small cached thumbnail/preview files get generated on disk. Today, when the original attachment or the message it belongs to gets deleted, those cached thumbnail files are never removed. Over months of use this quietly eats into the user's device storage for no benefit.

### Request

Add a routine that periodically finds thumbnail cache files that no longer correspond to any attachment or message still in the app, and deletes them.

### Constraints to respect

- This needs to run automatically in the background on some regular cadence — it shouldn't require the user to do anything, and it shouldn't be something that only happens once right after an app update.
- It must not make the UI feel janky or unresponsive — this is lower priority than anything the user is actively doing.
- It should not run while the user is on an active call.
- It should not run when the device's battery is critically low.
- There can be a lot of files to check on a device that's been used for a long time. If the process gets killed partway through a pass (which happens routinely on Android), the next attempt should make forward progress instead of either restarting the entire scan from the beginning every time, or giving up partway through and never finishing.

### Acceptance criteria

- Thumbnail files with no corresponding attachment/message are eventually deleted without user action.
- The cleanup respects the call/battery conditions above.
- A cleanup pass that gets interrupted partway resumes sensibly on a later attempt rather than restarting from scratch or stalling forever.
